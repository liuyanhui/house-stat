# 趋势报告网页化升级 — 需求文档 v0.3

> 版本史：v0.1（2026-10-26，独立 dashboard 方案）→ v0.2（路线改为演进现有报告 + 五角色评审吸收）→ **v0.3（2026-10-26）**：①数据边界升为硬规则（只用已爬数据，移除媒体引用锚点）；②新增统计维度增强（全部由现有字段派生）；③档位 B 定稿。

## 0. 决策状态（均已定）

- 路线：演进 `trend_report` 单产物，不做独立 dashboard（档位 C 退为后备）。
- 档位 B：内嵌 ECharts 轻交互（推荐获接受；档位 A 零 JS 为其严格子集，可随时退）。
- 数据边界（用户 2026-10-26 定）：**只用 `data/` 下已爬取的官方自爬 CSV，不依赖任何外部/第三方数据**。
- 维度增强：只用现有字段派生新指标，不新增抓取。

## 1. 目标与边界

- 目标：trend_report.html 保持"单文件、自包含、双击即开、无服务器"，①现有内容更严谨好读；②补齐新房/机构/长周期等缺失维度；③图表获得 hover/dataZoom/图例开关；④新增派生指标（去化周期等）。
- 不做：预测（只在 ai_digest 层）；任何第三方/媒体数据；跨图全局联动（报告语境不需要，`echarts.connect` 可后补）；数据库/后端/用户系统；新增抓取面。

## 2. 总体架构（档位 B）

- **md 仍是唯一中间源**：图表引用保持 `![](xxx.png)` 不变（md 可读性与 PNG fallback 不破）。
- **plots.py**：DataFrame→序列 data-prep 抽共用函数（防 matplotlib/ECharts 双实现漂移）；产 PNG 同时落 `report/charts/*.json`。
- **html_render.py**：按文件名将 `<img>` 替换为带显式高度 `<div>` + `<script type="application/json">` 数据块（转义 `</`）+ 文末统一 bootstrap（经典 script、UMD echarts、IntersectionObserver 懒 init）。
- **echarts vendor**：官方在线按需构建（bar/line/heatmap/tooltip/legend/dataZoom/toolbox/markLine，约 300–450KB），固定版本+sha256 提交 `assets/vendor/`，构建期内联。不引 npm/构建链。
- **表格**：Python 预写 `data-v` 排序键 + ~40 行原生 JS 事件委托（JS 零计算）；sticky 表头单独 max-height 容器。
- **交互边界**：每图独立 hover/dataZoom/图例；无跨图联动。
- **计算分层**：JS 允许切片/排序/筛选；禁止跨行算术（求和/占比/均线/同比一律 Python 预计算）。

## 3. 数据层前置（M1 地基）

1. `load.py` 补 `load_new_daily()` / `load_agency()`：-1 清洗、2026-08-23 字段全量边界、2026-09-16 缺失登记。其余脚本只消费 loader。
2. **quality_flags 结构化**：每数据集 meta `{coverage, estimated_days, missing_months, known_issues, notes}`，Python 统一产出随渲染下发；文字说明与图上标注同源。
3. **metrics 防护**：环比断档校验（上期≠上月→NaN）；同比仅连续 ≥13 月序列启用（当前仅全市月度），区县/面积段/机构显示"—"；MA 按序列长度降级；2025-01 总面积坏值置 NaN；new_daily 2026-04（仅 2 天）月度化剔除；机构口径="上榜机构内份额"。
4. **集成**：生成挂 `report.bat` 末尾（analyze 成功后串行），不并入 main.py；产物不入库。
5. **`--verify` 验收门**：完整性校验 + 锚点断言（最新月总量、区县 Top1、面积段占比和≈100%±5% 与 metrics 逐值相等）+ JSON 体积上限，不符非零退出。

## 5. 口径与纪律（成文规则）

1. JS 只做切片/排序/筛选，禁止跨行算术；派生指标一律 Python 预计算。
2. 断档处环比 NaN、序列断线禁插值。
3. 不完整周期必须与完整周期视觉区分，禁同列直接环比。
4. 估算数据在所有聚合层级携带标记，防被聚合"洗白"。
5. **只用已爬取的官方自爬数据；不使用、不引用任何第三方/媒体数据**（现有 H1 媒体参考表与 ai_digest H1 锚点一并移除）。
6. 无预测（预测只在 ai_digest 层）。
7. 新鲜度按数据集分别标注。
8. 每个新增派生指标（去化周期/退房率/TTM/YTD/非住宅占比）须：口径写入数据说明 + 挂 quality_flags。
9. **统计粒度（用户 2026-10-26 定）：月为主，周为最细**——存在合适序列时启用周度（如二手 77 周）；日度数据仅作周度聚合的输入，不作为分析或展示粒度；序列过短的（新房认购/签约，2026-08-23 起仅约 2 个月）退用月度。

## 6. 验收标准（可测）

- 生成期断言（进 `--verify`）：锚点 KPI 与 metrics 逐值相等；JSON 体积上限；新指标口径注释存在性检查；非零退出。
- file:// 实测清单：首屏 <2s；全部图表渲染/hover/dataZoom/saveAsImage；表格排序；中文显示。
- 回归：与 trend_report.md 数字抽查一致；PNG fallback 可用。

## 7. 分期

- **M1 基建+迁移**：§3 全部 + ECharts 注入管线 + 现有 10 图迁移。产物：内容不变、图表交互化、验收门生效。
- **M2 优化**：O1、O2、O3、O4、O5、O7（O6 可选；R5 可提前至此末段）。
- **M3 丰富**：R1（含去化/现房期房）→ R2 → R4 → R3（含退房率）。
- 档位 C 后备：交互需求超出时拆独立 dashboard，投入全沉淀。
